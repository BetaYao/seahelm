# First Mate 交互界面设计

日期：2026-11-04  
状态：核心交互方向已确认，边界行为为本文建议，待实现验证。

## 目标与范围

First Mate 提供一个持续存在的 Agent 会话，帮助用户关注各工作区进展、处理建议，并下达新的任务。不同入口适配不同的使用空间，共享同一会话、状态与待处理卡片。

本次设计覆盖 macOS Island 和 GPUI 主内容区。Island 适合快速查看、决策和短对话；主内容区适合完整操作，使用真实 terminal。

本设计更新早期 First Mate 文档中的界面方案，不重新定义自动化规则或执行权限。跨客户端的数据归属沿用 [First Mate in core](../../first-mate-core.md)；该文档的 GPUI 界面描述以本设计为准，后端迁移阶段仍以实际代码为准。

交互参考：[HTML 原型](../../first-mate-prototype.html)。原型使用演示数据，回复和卡片操作不连接真实 Agent，也不证明后端能力已完成。

## 已确认的设计决策

| 场景 | 形式 | 内容 |
| --- | --- | --- |
| 状态 1：收缩 | Island 胶囊；GPUI 左下角入口 | 用量、Agent 状态；待处理建议数量作为提示 |
| 状态 2：Island 有建议 | suggestion 卡片列表 | 列表独立滚动，最底部固定输入条 |
| 状态 3：Island 对话 | 自定义轻量 Agent UI | 没有建议时直接进入；有建议时点击输入条进入 |
| 状态 4：GPUI 展开 | 主内容区双栏 | 左侧真实 terminal agent，右侧 suggestion 卡片列表 |

Island 展开后的用量栏保持现有界面：左侧 Seahelm，右侧 Claude / Codex 的用量、周期和重置倒计时。建议列表和对话共享这一栏，切换时不移除、不改成新的统计样式。

Island 对话参考 seahelm-web Timeline 的表达方式，使用独立 UI 呈现消息和执行状态。出现在主内容区的 Agent 直接使用真实 terminal。

## 信息层级

First Mate 的界面由三个持续存在的信息部分组成：

1. **用量与状态**：帮助用户判断容量和当前运行情况。
2. **待处理建议**：展示需要用户做出决定的事情。
3. **Agent 会话**：接收自由指令、展示过程和结果。

Island 同时只展开建议或会话中的一个，以适应浮层空间。GPUI 主内容区同时展示两者，使用户可以边查看执行过程、边处理建议。

这里的 suggestion list 指统一待处理卡片队列的界面，可以包含建议、问题、选项、审批和报告。来源仍可能是各工作区里的 Agent；它们不必全部由 First Mate 生成。卡片必须显示关联项目和工作区，避免用户误判动作目标。

## 状态 1：收缩入口

### Island

沿用现有 Island 的黑色胶囊轮廓、屏幕顶部位置和状态色，展示简洁用量与 Agent 状态。

用户点击后：

- 有待处理建议：进入状态 2。
- 没有待处理建议：进入状态 3。

展开和收缩只改变可见界面，后台会话继续运行。

### GPUI

入口固定在左侧栏底部，展示 First Mate 标识、用量、状态及建议数。点击后在右侧主内容区打开状态 4；左侧工作区导航继续可用。

入口不直接展开 Island 式浮层，避免在主窗口内再叠一层小窗口。

## 状态 2：Island 建议列表

布局从上到下：

```text
┌──────────────────────────────────────────┐
│ Seahelm       Claude 用量 / Codex 用量    │
├──────────────────────────────────────────┤
│ First Mate                    待处理数量 │
│ ┌──────────────────────────────────────┐ │
│ │ 工作区 · 卡片内容 · 可选动作          │ │
│ └──────────────────────────────────────┘ │
│ ┌──────────────────────────────────────┐ │
│ │ 其他卡片                              │ │
│ └──────────────────────────────────────┘ │
│                 列表可滚动               │
├──────────────────────────────────────────┤
│ › 交给 First Mate…                       │
└──────────────────────────────────────────┘
```

列表内容过多时在列表内部滚动，底部输入条始终可见。用量栏不随列表滚动。

每张卡片包含：关联项目与工作区、核心问题或建议、必要的说明、可执行选项。具体按钮来自卡片数据，不在客户端按文案猜测行为。

点击卡片选项后，由共享业务层执行回答；客户端展示提交中和结果。不能仅凭本地点按就把卡片当成已完成。其他入口处理后，本入口同步移除或更新对应卡片。

点击底部输入条进入状态 3，建议队列保留。输入条是会话入口，不要求用户先解决全部建议。

## 状态 3：Island 轻量 Agent UI

### 进入方式

- 收缩入口展开时没有建议。
- 有建议时，用户点击底部输入条。

### 展示

顶部保留现有展开用量栏，下方为 First Mate 对话。内容区域展示用户消息、Agent 回复、必要的工具执行状态和结果，输入条固定在底部。

使用简洁对话排版，避免在小浮层中展示完整终端网格。长输出和工具详情默认压缩，用户可以展开查看；需要连续操作时，提供“在主窗口打开”的入口，打开同一个 First Mate 会话。

有待处理建议时，对话标题区保留“建议 N”入口，允许用户返回状态 2。对话切换不清空历史、输入草稿或建议。

参考 Web 的 Timeline 交互和消息语义；复用共享事件与数据模型。原生 Island 的 UI 实现可以独立，不要求嵌入网页。

### 输入

用户输入直接发送给 First Mate 会话。键盘提交需兼容输入法组合状态；输入法确认候选时不能提前发送消息。

发送失败时保留输入内容并提供重试。正在执行的过程需要明确状态与中断入口，中断使用会话实际能力，由共享层执行。

## 状态 4：GPUI 双栏工作台

```text
┌─────────────────┬─────────────────────────────────────────┐
│ 项目 / 工作区    │ First Mate                              │
│                 ├───────────────────────┬─────────────────┤
│                 │ Terminal Agent        │ Suggestion list │
│                 │                       │                 │
│                 │ 真实终端输入与输出    │ 工作区卡片       │
│                 │                       │ 选项 / 审批      │
│                 │                       │                 │
│                 │                       │                 │
│ First Mate      │                       │                 │
│ 用量 + 状态     │                       │                 │
└─────────────────┴───────────────────────┴─────────────────┘
```

点击左下角入口后，工作台占据右侧主内容区。左侧为 First Mate 的真实 terminal，保留终端选择、滚动、输入法、快捷键与程序交互；右侧为统一待处理卡片列表。

两侧独立滚动。处理卡片不应重建 terminal 或打断会话；终端持续输出也不应使右侧卡片滚动位置跳动。

没有建议时，右侧展示简洁空态，终端继续可用。关闭工作台或选择其他工作区时，恢复相应工作区内容，First Mate 后台会话保持存活。

主内容区不额外叠加一套聊天输入条；用户直接在 terminal 内操作 Agent。卡片动作通过共享接口执行，客户端不自行模拟按键回答。

## 状态切换规则

| 当前状态 | 事件 | 结果 |
| --- | --- | --- |
| Island 收缩 | 点击，队列非空 | 建议列表 |
| Island 收缩 | 点击，队列为空 | 轻量对话 |
| 建议列表 | 点击输入条 | 轻量对话，保留建议 |
| 轻量对话 | 点击“建议 N” | 建议列表，保留会话 |
| 任意 Island 展开态 | 收缩 | 返回胶囊，会话继续 |
| GPUI 左下角入口 | 点击 | 主内容区双栏工作台 |
| GPUI 工作台 | 关闭 / 选择其他工作区 | 返回对应工作区，会话继续 |

建议采用以下边界行为，作为实现默认值，尚未单独确认：

- 用户正在输入或阅读对话时，新建议只更新数量，不抢占当前界面。
- 建议列表的最后一张卡片处理完毕后，转到轻量对话；进入对话不自动抢键盘焦点。
- 用户主动点击输入条时，将焦点交给输入框；自动收到建议时不抢走其他应用焦点。
- Island 中 Esc 优先关闭局部弹出内容，再从对话返回建议或收缩。GPUI 真实 terminal 中的 Esc 交给终端程序，关闭工作台使用显式按钮。
- GPUI 双栏可调整宽度；终端优先获得空间。最小窗口尺寸和卡片栏折叠策略在实际布局验证后确定。

## 同一个会话，多种呈现

Island 和主内容区连接同一个 First Mate 会话。界面切换、窗口收缩和客户端重连不能创建第二个 First Mate，也不能重新执行任务。

“同一个会话”指会话身份、执行过程和操作结果一致；轻量对话与 terminal 不要求逐字符一致。对话呈现结构化消息，terminal 呈现真实终端内容。

各入口共享卡片 ID 与回答结果。用户在 Web、Telegram 或其他桌面入口处理卡片后，Island 和 GPUI 同步更新。过期卡片操作应返回已处理或已失效，不能重复执行。

## 数据与组件边界

| 组件 | 目标职责 |
| --- | --- |
| seahelm-core | First Mate 生命周期、统一卡片队列、业务状态与动作执行 |
| seahelmd | First Mate 的 PTY、进程、终端状态与输入输出 |
| seahelm-gateway | Web / Telegram 等外部接入、身份校验与数据转发 |
| Island | 用量展示、卡片列表、结构化对话 UI |
| GPUI 主内容区 | 真实 terminal 与卡片列表 |

这是目标分工，当前实现的迁移进度参见 [core 设计](../../first-mate-core.md)。本次界面设计不意味着 Gateway Rust 重写或 First Mate 后端迁移已经完成。

卡片接口沿用 core 文档中的 `cards.list`、`cards.answer`、`cards.dismiss` 和 `cards.changed`。用量沿用现有采集结果与格式规则，未知值继续显示占位，不伪装成 0%。

Island 对话需获得结构化会话消息、执行状态和可恢复历史。优先复用 seahelm-web 的消息事件语义；实现前需确认共享层提供事件的方式及历史恢复能力，不依赖从渲染后的 terminal 文本反推聊天消息。未能结构化的交互应提供打开真实 terminal 的入口。

## 异常和恢复

- 连接中断：展示连接状态，保留现有内容；恢复快照前，暂停卡片执行。
- Agent 未启动：区分未启动、启动中和启动失败，失败时可重试。
- 卡片提交失败：保留卡片并显示失败原因，允许重试。
- 重连：恢复会话和卡片快照，按消息标识去重；不重复发送用户指令。
- 多个客户端同时打开：允许多入口观察，执行仍由同一共享会话与业务层协调。terminal 尺寸协商需验证，避免附着不同大小界面导致工作区终端异常缩小。

## 验收标准

1. Island 收缩可查看用量与状态；展开用量栏与现有样式、数据含义一致。
2. 有建议时打开卡片列表，长列表滚动不会遮住底部输入条。
3. 点击输入条进入自定义 Agent 对话；无建议时从收缩直接进入对话。
4. 对话中可返回建议，切换不丢失会话、草稿或卡片。
5. GPUI 左下角入口可打开主内容区双栏，左侧是真实 terminal，右侧是卡片。
6. 关闭界面不会停止 Agent；再次打开恢复同一会话。
7. 卡片在其他客户端被处理后同步更新；重复点击不重复执行。
8. 新建议到达不抢占正在进行的对话或输入法操作。
9. 用量缺失、断线、Agent 启动失败和发送失败都有明确的可恢复状态。

以上需分别通过状态切换验证、真实会话联调和桌面视觉检查。HTML 原型仅用于确认布局与交互方向。
